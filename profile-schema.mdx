Profiles are plain UTF-8 JSON files stored in the `profiles/` directory, one file per profile. The filename is always `<nombre>.json` where `nombre` matches the `nombre` field inside the file. The control panel reads and writes these files through the REST API; `server.ps1` creates a `default.json` automatically on first run if the directory is empty.

## Top-level fields

<ParamField path="nombre" type="string" required>
  Profile name, used as both the display label in the panel and the filename on disk (`profiles/<nombre>.json`). The server strips any character that is not alphanumeric, a hyphen, an underscore, or a space before saving.
</ParamField>

<ParamField path="paquete" type="string" required>
  Android package name of the game under test (e.g. `com.fluffyfairygames.idleminertycoon`). This is the app launched at the rolled-back date and again at the restored real date.
</ParamField>

<ParamField path="paqueteBrave" type="string" default="com.brave.browser">
  Package name of the browser app opened between the two game launches. Switching apps forces the game to reload when it returns to the foreground.
</ParamField>

<ParamField path="diasAtraso" type="integer" default="30">
  Calendar days to subtract from the current date when rolling back the device clock.
</ParamField>

<ParamField path="iteraciones" type="integer" default="10">
  Number of complete test cycles to run in a single execution.
</ParamField>

<ParamField path="timeoutSegundos" type="integer" default="15">
  Maximum seconds to wait for an app to reach the foreground after being launched via ADB.
</ParamField>

<ParamField path="segundosVentana" type="integer" default="2">
  Extra pause in seconds after the reward sequence finishes, before the next cycle begins.
</ParamField>

<ParamField path="pasosRecompensa" type="array">
  Ordered list of step objects that make up the reward interaction sequence. Steps are executed in array order after the game reopens with the real date. See the [Step object](#step-object-pasosrecompensa-items) section below for the shape of each item.
</ParamField>

## Step object (`pasosRecompensa` items)

Each element of `pasosRecompensa` is an object with the following fields.

<ParamField path="id" type="string">
  Unique step identifier used internally by the UI to track reordering and deletion. Auto-generated by the panel as a short random string (e.g. `s3k9f2a`). You may assign any unique string when editing the file by hand.
</ParamField>

<ParamField path="etiqueta" type="string">
  Human-readable label displayed in the panel step list and written to every log line that corresponds to this step (e.g. `"Tocar boton 'x2 Gratis'"`).
</ParamField>

<ParamField path="tipo" type='"esperar" | "tap"' required>
  Step type. Use `"esperar"` to pause execution for a fixed number of seconds, or `"tap"` to send a touch event to the device screen at fractional coordinates.
</ParamField>

<ParamField path="segundos" type="integer">
  *(Only for `tipo: "esperar"`)* Number of seconds to pause before advancing to the next step.
</ParamField>

<ParamField path="fx" type="number (0.0 – 1.0)">
  *(Only for `tipo: "tap"`)* Horizontal tap position as a fraction of the screen width. `0.0` is the left edge; `1.0` is the right edge. The server multiplies this by the device's physical width (obtained via `adb shell wm size`) to compute the absolute pixel coordinate.
</ParamField>

<ParamField path="fy" type="number (0.0 – 1.0)">
  *(Only for `tipo: "tap"`)* Vertical tap position as a fraction of the screen height. `0.0` is the top edge; `1.0` is the bottom edge.
</ParamField>

<ParamField path="reintentos" type="integer">
  *(Optional, only for `tipo: "tap"`, minimum 1)* How many times to send the tap command. Defaults to `1` if omitted. Useful for buttons that require multiple presses or are occasionally unresponsive.
</ParamField>

<ParamField path="esperaEntreReintentos" type="integer">
  *(Optional, only for `tipo: "tap"`)* Seconds to wait between consecutive tap retries when `reintentos` is greater than `1`. Defaults to `1` if omitted.
</ParamField>

## Example profile

The following is the content of `profiles/default.json` as shipped with the project. It targets **Idle Miner Tycoon** and includes a six-step reward sequence covering the initial popup, the ad button, the close button, and the collect button.

```json
{
  "nombre": "default",
  "paquete": "com.fluffyfairygames.idleminertycoon",
  "paqueteBrave": "com.brave.browser",
  "diasAtraso": 4,
  "iteraciones": 6,
  "timeoutSegundos": 15,
  "segundosVentana": 2,
  "pasosRecompensa": [
    { "id": "p1", "etiqueta": "Esperar popup inicial",    "tipo": "esperar", "segundos": 2 },
    { "id": "p2", "etiqueta": "Tocar boton 'x2 Gratis'", "tipo": "tap",     "fx": 0.304, "fy": 0.678, "reintentos": 1 },
    { "id": "p3", "etiqueta": "Esperar anuncio/carga",   "tipo": "esperar", "segundos": 6 },
    { "id": "p4", "etiqueta": "Tocar 'X' de cierre",     "tipo": "tap",     "fx": 0.925, "fy": 0.032, "reintentos": 1 },
    { "id": "p5", "etiqueta": "Esperar tras cerrar la X","tipo": "esperar", "segundos": 2 },
    { "id": "p6", "etiqueta": "Tocar 'Recolectar'",      "tipo": "tap",     "fx": 0.499, "fy": 0.732, "reintentos": 1, "esperaEntreReintentos": 2 }
  ]
}
```

## Example — minimal profile

A profile with no reward steps is valid. The run still performs the date rollback, app switching, and date restore cycle — it just skips the tap/wait sequence after reopening the game. Useful as a starting point when calibrating a new game.

```json
{
  "nombre": "simple",
  "paquete": "com.example.mygame",
  "paqueteBrave": "com.brave.browser",
  "diasAtraso": 30,
  "iteraciones": 10,
  "timeoutSegundos": 15,
  "segundosVentana": 2,
  "pasosRecompensa": []
}
```

<Tip>
  Profiles are plain UTF-8 JSON — you can open them in any text editor, make changes, and save. The panel picks up the updated content the next time you load the page or switch profiles in the dropdown. No server restart is required.
</Tip>
